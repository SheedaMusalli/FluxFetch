# FluxFetch v2.0.0 — Torrents, live progress, and installer updates

FluxFetch 2.0 added built-in torrents, a redesigned OmniLink overlay, Firefox support, and a themed Windows installer. The library footer and tray show download and torrent progress.

## What's new

### Torrents, inside FluxFetch

- A bundled **libtorrent** session handles magnets and `.torrent` files directly. No separate client, Web UI or Python installation is needed.
- Pause/resume, seeding, tracker/DHT discovery, saved-session recovery and per-torrent rate limits.
- **Torrent details** exposes file progress, tracker replies/errors, connected peers, ETA, uploads, ratio, DHT nodes and listening port.
- **Saving to** shows the full content path, with **Open download folder**. The content folder is created when metadata arrives, before pieces finish downloading.
- Separate **Remove torrent (keep files)** and confirmed **Delete torrent and files** actions.
- Windows Open With registration for `.torrent` files and magnet handling, with a destination confirmation before adding.
- Fixed unsupported DHT alert handling. New/restored jobs clear sequential mode and use normal swarm piece selection. Discovery contacts supplied trackers across tiers. Peer/request tuning preserves rate limits; actual speed depends on the swarm and connection.

### Progress in the library and tray

- Live normal/torrent status, percentage, rates and progress bars in the main library footer.
- Hover over the tray icon for combined progress and speed.
- **Paused**, **Cancelled** and **Failed** library cards, alongside existing filters.
- Batch history removal and a separate confirmation when deleting a file from disk.

### OmniLink for Steam

- A smaller, opaque FluxFetch-themed overlay with expandable details.
- Steam running/download activity and Steam throughput, with zero speed when no game download is detected.
- Connection counts, per-adapter throughput, IP addresses, gateways and link information.
- Automatic detection of new routable adapters, reconnects and address changes while running.

OmniLink can use independent connections for eligible Steam transfers: Ethernet through Router A, Wi-Fi through Router B, and Android USB tethering using Router C's Wi-Fi where supported. Those routers need separate upstream capacity. Multiple adapters on one Internet line do not add bandwidth. Administrator approval and compatible drivers are required; a speed increase is not guaranteed.

### Browser and installation improvements

- Chromium and Firefox extension packages **v1.4.1**, browser handoff, direct media and supported public-YouTube downloads.
- Automatic capture skips ordinary images and known files smaller than 128 KiB; explicit actions and torrents are handled separately.
- Fixed first-use media-tool setup. App-data paths and browser helper identity now use FluxFetch, with migration for existing profiles.
- Fixed browser connection failures caused by rejecting Windows Chromium's native-host parent-window argument. Chromium and Firefox launches keep their extension identity checks.
- Dark Windows setup with styled navigation, license acceptance and installation options.
- **Update** preserves settings/history. **Fresh install** resets this account's settings, credentials and history while retaining downloaded files. Setup automatically closes the running app.
- Update checks point to **FluxFetch's GitHub releases**.

## Install FluxFetch

1. Download and run **fluxfetch-2.0.0-setup.exe** on Windows 10/11 x64.
2. Review the license, choose the available options and installation folder, then install. Existing users can select **Update** or **Fresh install** as described above. Setup closes the running app automatically.
3. Open FluxFetch and choose a save folder in **Settings**.
4. Install the appropriate browser extension below for webpage capture.

### Chrome, Edge, Brave, Vivaldi, Opera / Opera GX

1. Extract **FluxFetch-Chrome.zip** into a permanent folder.
2. Open `chrome://extensions`, `edge://extensions`, `brave://extensions`, `vivaldi://extensions` or `opera://extensions`. Other Chromium browsers: open their extension management page.
3. Enable **Developer mode**, choose **Load unpacked**, and select the folder directly containing **manifest.json**.
4. Pin **FluxFetch Download Manager**, confirm **Connected** in its popup, and refresh webpages.

Keep the extracted folder. Other Chromium forks need compatible Manifest V3 and Native Messaging support; loading alone does not confirm desktop connectivity. Use the ZIP where off-store CRX installation is restricted.

### Firefox

Install FluxFetch for Firefox from [Mozilla Add-ons](https://addons.mozilla.org/en-US/firefox/addon/fluxfetch-integration-module/).

The installer registers the local helper; browser extension loading remains a separate step. Read the [README](https://github.com/SheedaMusalli/FluxFetch#readme) for features and usage, and the [browser guide](https://github.com/SheedaMusalli/FluxFetch/blob/main/docs/BROWSER-SETUP.md) for setup, updates and troubleshooting.

## Upgrade notes and validation

- Replace/reload older extensions after updating the desktop app. Preserve the Chromium manifest key and Firefox ID.
- Older aria2 sessions are not imported: re-add the same torrent with the same destination to verify and reuse existing files.
- The installer is not publisher-signed. Checksums identify release files, but are not a publisher signature.
- Media tools download on first use. DRM, live broadcasts, interactive challenges and some restricted videos remain unsupported.
- Local validation includes the TypeScript/app build, four Electron torrent tests, and a real local-peer transfer with byte verification, resume recovery, folder visibility and keep/delete behavior. Public-swarm speed gains and compatibility with every browser fork are not claimed.
