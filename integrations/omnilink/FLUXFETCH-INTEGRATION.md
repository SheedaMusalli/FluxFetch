# FluxFetch OmniLink integration

This directory contains the OmniLink source integrated into FluxFetch. The redesigned overlay is a compact, opaque FluxFetch dark-theme card with a Steam status badge, live Steam-only speed, and expandable per-adapter measurements.

`npm run build:omnilink` builds the Windows x64 tray helper from this source and stages its executable, WinDivert runtime files, and license into `resources/omnilink`. The Windows installer build runs this step automatically. Rust's stable MSVC toolchain is required.

The FluxFetch **Run OmniLink** button starts the helper through Windows' standard administrator-consent flow. The helper uses WinDivert to intercept Steam HTTP(S) traffic and attempt per-connection multi-adapter routing. OmniLink rescans routable adapters every two seconds while running, adding newly connected adapters automatically and refreshing changed addresses or routes without a restart. New adapters are enabled by default; existing enable/disable choices are kept across scans. The tray menu still offers a manual refresh and controls bonding and overlay visibility. The overlay and tray speed readings count payload bytes on intercepted Steam streams only. They show zero when Steam is not running or no Steam download data arrived during the latest sample window, and identify Steam as not running, running, or downloading. FluxFetch does not silently elevate, configure Windows routes, or claim that every Steam download/CDN will combine links. Actual throughput depends on the user's independent Internet connections and Steam's servers.

OmniLink's live interception and Steam download behavior remain a manual hardware validation step; a successful compile or unit test does not prove a given PC/network configuration will accelerate Steam. WinDivert's dual LGPLv3/GPLv2 license notice is copied alongside the source and is included with the packaged helper.
